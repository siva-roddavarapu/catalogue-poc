## Assumptions

| #   | Gap                               | Decision                                                                                                                                                                                                                                             | Why                                                                                                                                         | How to change later                                                                     |
| --- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| A1  | What "top rated" means (AC1, AC2) | The owner curates it in `config/merchandising.json` (`homeFeatured`: 5 IDs, `categoryFeatured`: slug → IDs). Fake Store `rating` is not used.                                                                                                        | The AC says "GIVEN **I have chosen** 5 products". Curation is owner data, not API data.                                                     | Replace `JsonFileMerchandising` with a CMS- or DynamoDB-backed `MerchandisingProvider`. |
| A2  | Bad curation data                 | Startup check: `homeFeatured` must hold exactly 5 unique IDs, or the app fails fast. IDs missing at runtime are skipped and logged as a warning. The same skip-and-warn rule applies to `categoryFeatured` IDs outside their category.               | A config typo should fail at boot. Products disappearing upstream is normal and shouldn't take the site down.                               | Same rules apply in any provider.                                                       |
| A3  | A category with no curation       | `topRated` is `[]`. The UI shows only "More in this category".                                                                                                                                                                                       | AC2 needs top rated **and** additional products, but uncurated categories can exist.                                                        | Add curation entries.                                                                   |
| A4  | Category identity in URLs         | URL-safe slug (`mens-clothing`) plus display name. The adapter maps slug → upstream name. Unknown slug → 404. Upstream's misspelt `jewelery` is kept as-is ("Jewelery").                                                                             | Upstream names contain spaces and apostrophes. Fixing the source's data isn't the adapter's job.                                            | Another data source supplies its own slugs.                                             |
| A5  | Search semantics (AC3)            | Trim the term. Case-insensitive substring match on title, description and category. Runs server-side over the cached list. Empty term → 400 (the UI disables the button); max 100 chars.                                                             | Fake Store has no search endpoint. "Only see products with text matching" is read as substring.                                             | Use a source with a search index behind the same service method.                        |
| A6  | Currency (AC4)                    | `CURRENCY` env var (default `USD`), validated at startup with `Intl.NumberFormat`. How the web app learns it is open question Q17.                                                                                                                   | Fake Store prices carry no currency.                                                                                                        | Take currency from the data source once it provides one.                                |
| A7  | Product detail content (AC4)      | Image, title, price, category, description, Enquire button. Rating is not shown.                                                                                                                                                                     | Rating isn't used for anything (A1), and showing it would invite confusion with "top rated".                                                | Add to `ProductPage`.                                                                   |
| A8  | What a product tile shows         | Image (alt = title), title, formatted price. The whole tile links to `/product/:id`.                                                                                                                                                                 | That's the minimum for browsing, and it satisfies AC4's "click a product tile".                                                             | Edit `ProductTile`.                                                                     |
| A9  | Enquiry fields (AC5)              | name (2–100), email, phone (optional, 7–20 chars of digits/spaces/`+()-`), message (optional, ≤1000), hidden productId. One shared Zod schema; the server is authoritative.                                                                          | "Contact details" isn't defined in the brief.                                                                                               | Edit the shared schema.                                                                 |
| A10 | Trusting client data in the email | The server re-fetches the product by ID (unknown → 404). Subject `New enquiry: <title>`, plain text, Reply-To = customer, product link `${WEB_ORIGIN}/product/:id`. CR/LF rejected in header-bound fields. Response `202 { id }` with a random UUID. | Stops spoofed product data and header injection. The UUID appears in the email and the logs so an enquiry can be traced without a database. | Persist enquiries; the id becomes the DB key.                                           |
| A11 | "Sales inbox receives an email"   | Mailpit in Docker Compose (SMTP :1025, inbox UI :8025) via `SmtpEmailSender`. No SMTP auth.                                                                                                                                                          | Free, local, and the reviewer can see it work.                                                                                              | `SesEmailSender` adapter (documented, not built).                                       |
| A12 | Upstream resilience               | 5 s timeout, in-memory TTL cache (default 300 s). Upstream down and cache empty → 502. Single products come from the cached list, not `/products/:id`. `PRODUCT_SOURCE=fixture` uses the committed snapshot.                                         | Verified: Fake Store answers an unknown ID with **HTTP 200 and an empty body**, so using the list is simpler and correct.                   | Shared cache (e.g. ElastiCache) when there is more than one instance.                   |
| A13 | Product ID format                 | A positive integer. Anything else → 400.                                                                                                                                                                                                             | Matches the source. Validation lives at the edge.                                                                                           | Switch to a string ID in the shared schema if a new source needs one.                   |
| A14 | Product images                    | The browser loads image URLs (currently on fakestoreapi.com) that our API returns. All product **data** still goes only through our API.                                                                                                             | An image is an asset referenced by URL. Proxying images would be extra scope no AC asks for.                                                | A new source or CDN supplies the URLs. Nothing in the client changes.                   |
| A15 | Security basics                   | helmet, rate limit (5/min/IP) on `POST /api/enquiries`, body size limit, Zod validation on every param, query and body. No auth.                                                                                                                     | The brief has no logged-in users. See S5/S6 for what was cut.                                                                               | Add auth when accounts exist.                                                           |
| A16 | AWS compatibility                 | Stateless API container (ECS Fargate / App Runner), static web build (S3 + CloudFront), SES, DynamoDB/CMS. Documented only: no IaC, **no deployment** (the brief doesn't ask for one).                                                               | Time-box.                                                                                                                                   | Add CDK/Terraform.                                                                      |
| A17 | Where the project lives           | A new, dedicated repo. `main` = initial commit; work on `feature/catalogue-poc`; PR into `main` left open.                                                                                                                                           | Owner's decision.                                                                                                                           | n/a                                                                                     |
| A18 | Web port under Docker             | nginx serves the built app on host port **5173**, the same as `npm run dev`.                                                                                                                                                                         | One URL and one `WEB_ORIGIN` for both run modes.                                                                                            | n/a                                                                                     |

## Simplifications agreed before the build (owner-approved)

The aim is code the owner can defend line by line. Each cut is deliberate.

| #   | Spec said                             | We did                                                                     | Why                                                                                                                                       |
| --- | ------------------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| S1  | MSW for web tests                     | `vi.mock` of `src/api/client.ts`                                           | The client is the frontend's only network boundary, so mocking it there tests the same thing with one less tool.                          |
| S2  | Generic `lib/cache.ts`                | Timestamp and array inside the Fake Store adapter                          | Only one thing is cached. A generic cache is speculative.                                                                                 |
| S3  | One retry on network error            | Timeout only                                                               | Fewer branches to test and explain. The fixture switch is the offline fallback.                                                           |
| S4  | `scripts/refresh-fixture.ts`          | Snapshot generated once and committed; README documents a one-line refresh | No extra script to maintain.                                                                                                              |
| S5  | CORS restricted to the web origin     | **No CORS plugin**                                                         | The browser only calls same-origin `/api`, through the Vite proxy or nginx. Nothing is cross-origin, so a CORS rule would be dead config. |
| S6  | Honeypot field                        | Not built                                                                  | The rate limit covers basic abuse for a PoC. Listed under "next day".                                                                     |
| S7  | (implicit) a compile step for the API | `tsx` runs the TypeScript directly, in dev and in the container            | One runtime, no build output to keep in sync. A bundled `node dist/server.js` is a next-day item.                                         |

## Dropped (out of scope) and why

Pagination, sorting and filters, cart and checkout, auth, admin UI for curation (the JSON file is the admin), i18n, analytics, SSR/SEO, deployment and pipeline, enquiry persistence, customer confirmation email. No AC asks for them, and the time-box is 2–3 h.
